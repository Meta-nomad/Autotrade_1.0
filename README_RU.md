# Order Flow Paper Lab

Автоматический **paper-trading** стенд для агрессивной криптостратегии. Он получает реальные публичные данные MEXC, Bybit и Binance, но все заявки, позиции и деньги существуют только внутри SQLite-симулятора.

> В проекте нет клиента выставления ордеров, API-ключей и режима live execution. `live` в `DATA_MODE` означает только живые рыночные данные.

## Что сравнивается

Каждый счёт получает независимые 1 000 USDT (или значение `PAPER_BALANCE`):

| Виртуальный счёт | Логика | Риск на сделку | Макс. расчётное плечо |
|---|---|---:|---:|
| `CONTROL_20` | Контроль: пробой 20 свечей 15m + объём 1,5× + EMA200 на 1h | 2,0% | 5× |
| `ORDER_FLOW` | Тренд/пробой/ликвидационный разворот + tape, стаканы, OI, funding | 1,5% | 5× |
| `ORDER_FLOW_TURBO` | Те же сигналы, более агрессивный размер | 3,0% | 8× |

Order-flow модель объединяет:

- агрессивные покупки/продажи по фактическим сделкам на трёх биржах;
- imbalance и microprice стаканов MEXC/Bybit/Binance;
- согласие направления между площадками;
- изменение open interest, funding и поток ликвидаций Bybit;
- тренд, расположение в 30-минутном диапазоне и расширение волатильности;
- три сетапа: `TREND_PULLBACK`, `EXPANSION_BREAKOUT`, `LIQUIDATION_REVERSAL`.

Симулятор учитывает taker-комиссию на входе и выходе, глубину стакана Bybit как оценку проскальзывания, funding, стоп, тейк, безубыток после 1,5R, разворот order flow, time-stop и приближенную ликвидацию. Мартингейла и усреднения нет.

## Что требуется от владельца

- аккаунт Railway для круглосуточного запуска;
- выбранный игровой баланс (по умолчанию 1 000 USDT на каждый из трёх счетов);
- длинный случайный `DASHBOARD_TOKEN`;
- никаких биржевых аккаунтов и API-ключей.

## Быстрый локальный тест

### Docker

```bash
cp .env.example .env
# Для демонстрации без интернета поменяйте DATA_MODE=synthetic и DB_PATH=/data/paper_trader.db
docker compose up --build
```

Откройте `http://localhost:8000/?token=значение-DASHBOARD_TOKEN`.

### Python

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
DATA_MODE=synthetic DB_PATH=data/paper_trader.db DASHBOARD_TOKEN=demo python -m app
```

Windows: запустите `run_local.bat`; он включает синтетический поток, создаёт локальную БД и печатает адрес dashboard с тестовым токеном.

## Развёртывание на Railway

1. Распакуйте проект и загрузите его в приватный GitHub-репозиторий либо выполните `railway init`, затем `railway up` из папки проекта.
2. В Railway создайте persistent volume и смонтируйте его в `/data`. Без volume история исчезнет при пересоздании контейнера.
3. Добавьте переменные из `.env.example`. Для первого боевого paper-запуска нужны как минимум:

```text
DATA_MODE=live
PAPER_BALANCE=1000
DB_PATH=/data/paper_trader.db
DASHBOARD_TOKEN=<длинная случайная строка>
RAILWAY_RUN_UID=0
```

4. В `Settings → Networking` создайте публичный домен.
5. Откройте `https://ваш-домен/?token=<DASHBOARD_TOKEN>`.
6. Проверьте `/health`: `status` после прогрева должен стать `ok`, `paper_only` — `true`, а `live_trading_enabled` — `false`.

После запуска в Railway должны появиться строки `LIVE FEEDS STARTED`, затем
`PAPER STATUS` раз в минуту. В них видны `online/offline` и накопленное число
сообщений по каждой бирже. Отсутствие сделок само по себе нормально: стратегия
ждёт полный сетап, но счётчики подключённых потоков должны постоянно расти.

Railway автоматически собирает `Dockerfile`. Отдельная команда запуска не нужна. `RAILWAY_RUN_UID=0` требуется потому, что Railway монтирует volume от root, а Docker-образ по умолчанию запускает приложение от непривилегированного пользователя.

## API наблюдения

Все методы только для чтения:

- `GET /health` — техническое состояние без токена;
- `GET /api/status` — счета, позиции, фиды и признаки;
- `GET /api/trades?limit=100` — закрытые сделки;
- `GET /api/signals?limit=100` — сигналы, включая причины и feature snapshot;
- `GET /api/equity/ORDER_FLOW?limit=1000` — кривая капитала;
- `GET /docs` — схема API.

Токен передаётся через `?token=...` или заголовок `X-Dashboard-Token`.

## Проверка перед оценкой результата

Не меняйте параметры первые 30 дней. Разумный минимальный эксперимент — 60–90 дней и не меньше 300 закрытых сделок суммарно. Сравнивайте не только доходность, но и просадку, expectancy в R, комиссии, долю прибыльных недель и стабильность по отдельным монетам.

Цель +50–100% за месяц остаётся агрессивной гипотезой, а не ожидаемой или гарантированной доходностью. Виртуальный стенд нужен как раз для того, чтобы количественно проверить, достигается ли она и какой ценой по просадке.

## Сброс игрового эксперимента

Остановите сервис, удалите только файл `paper_trader.db` вместе с `-wal`/`-shm` в смонтированном томе и запустите снова. Это необратимо удалит виртуальную историю, поэтому предварительно сохраните копию БД.
