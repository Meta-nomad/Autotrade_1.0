# Order Flow Paper Lab 0.3

Автоматический **paper-trading** стенд для криптофьючерсов. Он получает публичные данные MEXC, Bybit и Binance, но деньги, позиции и исполнения существуют только в SQLite-симуляторе.

> В проекте нет клиента выставления ордеров, API-ключей и режима реального исполнения. `DATA_MODE=live` означает живые рыночные данные, а не живые заявки.

## Что изменилось в 0.3

Вместо пяти счетов и конкурирующих стратегий работает один портфель `COMPOSITE_FLOW` с единым решением:

1. прогрев и подтверждение устойчивого режима рынка;
2. собственный 4H-тренд каждой монеты и направление широкого рынка;
3. cross-sectional rank среди десяти ликвидных контрактов;
4. пробой диапазона предыдущих 20 завершённых 4H-свечей;
5. подтверждение объёмом, сделками, стаканом и согласием площадок;
6. следующий вход только после всех фильтров;
7. единый риск-менеджер, не допускающий дублирующих позиций.

Fibonacci и подтверждённые трендовые/pivot-структуры рассчитываются и попадают в диагностику сигнала. Они **не используются как самостоятельный вход или обязательный фильтр**: отдельные исторические варианты красиво выглядели на периоде разработки, но провалились на независимом периоде. Полный разбор находится в `research/REPORT_RU.md`.

## Исполнение и риск

- один виртуальный счёт, по умолчанию 1 000 USDT;
- риск 0,35%, 0,50% или 0,60% текущего equity в зависимости от score;
- суммарный открытый риск не выше 1,20%;
- максимум две позиции и не более одной монеты из корреляционного кластера;
- расчётное плечо не выше 5× и загрузка маржи не выше 75%;
- стоп 2,2 ATR, но не ближе 1,2% и не дальше 6%;
- целевой результат 5R после оценочных комиссий, безубыток и ATR trailing stop;
- дневной стоп −2%, месячный −8%, остановка после трёх стопов за день;
- без мартингейла, усреднения и увеличения риска после убытка.

Исторический тест не подтвердил 50–100% в месяц. Независимый период 2024–2026 оказался слегка отрицательным, поэтому версия 0.3 — исследовательский paper-кандидат, а не основание включать реальные деньги.

## Что требуется

- Railway либо любой Docker-хост;
- persistent volume, смонтированный в `/data`;
- выбранный игровой баланс;
- длинный случайный `DASHBOARD_TOKEN`;
- биржевые аккаунты и API-ключи не нужны.

## Быстрый локальный тест

### Docker

```bash
cp .env.example .env
# Для офлайн-демонстрации установите DATA_MODE=synthetic и DB_PATH=/data/paper_trader_v030.db
docker compose up --build
```

Откройте `http://localhost:8000/?token=значение-DASHBOARD_TOKEN`.

### Python

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
DATA_MODE=synthetic DB_PATH=data/paper_trader_v030.db DASHBOARD_TOKEN=demo python -m app
```

В Windows можно запустить `run_local.bat`.

## Развёртывание на Railway

1. Распакуйте проект и загрузите в приватный GitHub-репозиторий либо выполните `railway init`, затем `railway up` из папки проекта.
2. Создайте persistent volume и смонтируйте его в `/data`.
3. Добавьте переменные:

```text
DATA_MODE=live
PAPER_BALANCE=1000
DB_PATH=/data/paper_trader_v030.db
DASHBOARD_TOKEN=<длинная случайная строка>
RAILWAY_RUN_UID=0
```

4. В `Settings → Networking` создайте публичный домен.
5. Откройте `https://ваш-домен/?token=<DASHBOARD_TOKEN>`.
6. Проверьте `/health`: должны быть `version=0.3.0`, `paper_only=true`, `live_trading_enabled=false`, а после прогрева `status=ok`.

Railway собирает `Dockerfile`; отдельная start-команда не нужна. Новый путь `/data/paper_trader_v030.db` сохраняет старую базу и начинает чистый эксперимент 0.3.

## Как понять, что сервис работает

В Railway Logs сначала появляются:

```text
SERVICE READY version=0.3.0 ...
LIVE FEEDS STARTED venues=mexc,bybit,binance
MEXC BOOTSTRAP COMPLETE history_ready=10/10
```

Через пять секунд и затем каждые 30 секунд выводится `PAPER STATUS`. В нём есть:

- `feeds` — online/offline и растущие счётчики сообщений;
- `ready` — сколько монет прогрето;
- `blockers` — конкретные причины отсутствия сигнала;
- `regime` и `raw_regime` — подтверждённый и сырой режим;
- `equity`, `realized`, `floating`;
- `signals`, `opens`, `closes`, `positions`.

Ноль сделок допустим: 4H-сигнал редкий. Неподвижные счётчики сообщений, постоянный `ready=0/10` или растущий `engine_lag` — уже диагностический признак проблемы.

## API наблюдения

Все методы только для чтения:

- `GET /health` — версия и состояние движка без токена;
- `GET /api/status` — счёт, позиции, фиды и признаки;
- `GET /api/trades?limit=100` — закрытые сделки;
- `GET /api/signals?limit=100` — сигналы с причинами и snapshot признаков;
- `GET /api/diagnostics` — последнее решение и блокеры по каждой монете;
- `GET /api/equity/COMPOSITE_FLOW?limit=1000` — кривая капитала;
- `GET /docs` — схема API.

Токен передаётся через `?token=...` или `X-Dashboard-Token`.

## Срок paper-проверки

Параметры 0.3 следует заморозить минимум на 90 дней. Но из-за редких 4H-сигналов календарного срока недостаточно: решение о дальнейшем использовании принимается не раньше 200 закрытых сделок. До этого оцениваются только исправность потоков и соответствие исполнения модели.

Предварительный критерий допуска следующей версии: out-of-sample profit factor выше 1,10, положительное expectancy после комиссий и отсутствие расхождения бумажного исполнения с исторической моделью. Версия 0.3 этот исторический критерий пока не прошла.
